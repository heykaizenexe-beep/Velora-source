# Релизная подпись Velora — правила безопасности

Сборка `python rebuild.py --compile-home` использует **тестовый ключ**. Он не предназначен для публикации и может иметь известный пароль. Опция `--release` заблокирована.

Для выпуска в магазине после Gradle-миграции:

1. Создайте upload-keystore вне каталога репозитория на доверенном компьютере. Пример команды: `keytool -genkeypair -v -keystore C:\SecureKeys\velora-upload.p12 -storetype PKCS12 -alias velora-upload -keyalg RSA -keysize 3072 -validity 10000`. Вводите пароли интерактивно, не помещайте их в командную строку.
2. Сделайте зашифрованную резервную копию, отдельно запишите alias и процедуру восстановления. Не загружайте ключи и пароли в Git, переписку или логи.
3. Настройте Play App Signing; в защищённом GitHub Actions environment используйте секреты только для release-пайплайна, не для запросов из форков.
4. Перед публикацией проверьте `apksigner verify --verbose`, applicationId, versionCode, архитектуры и сценарии обновления старого приложения.

Файлы подписи (`signing/`, `*.p12`, `*.jks`, `*.keystore`) уже исключены из Git. Существующий тестовый ключ нужен для установки последующих тестовых APK поверх предыдущих без удаления данных.
